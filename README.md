# Academy ERP

A management app for activity academies: admissions, attendance, fees with online payment, WhatsApp communication, enquiries, expenses and finance reports.
Built on Google Sheets + Apps Script, with **one copy per institution** and one shared codebase.
First customer: **Rays Academy** (`Rays_Academy_PRD.md`).

## Repository layout

| Path | What |
|---|---|
| `docs/` | Plan, PRD addendum, schema, API contract, screens, provisioning runbook, owner inputs, decisions |
| `backend/` | Apps Script source, pushed with clasp. `Schema.js` is the source of truth for the data model. |
| `frontend/` | Static PWA served from GitHub Pages (scaffolded in phase 1) |
| `worker/` | Cloudflare Worker that verifies and forwards Razorpay webhooks |
| `tenants/` | Public per-institution config: branding, labels, modules, API URL. **No secrets.** |
| `presets/` | Seed data by academy type: categories, courses, fee plans, templates, custom fields |
| `scripts/` | Provisioning and deploy-all tooling (phase 7) |
| `deploy/` | Per-tenant clasp state and registry. **Git-ignored.** |

## Status
- **Phase 0, done:** docs, schema, backend core (router, auth, Db layer, migrations, seed), presets, tenant configs, webhook Worker skeleton.
- **Phase 1, done:** the frontend.
  - Academy chosen from the URL, with per-academy branding, labels and modules.
  - Login with session expiry.
  - Desktop sidebar and mobile bottom tabs, global search, sync indicator, API version banner.
  - Data loaded at login, delta sync, and an IndexedDB cache per academy.
  - Settings: profile, password, data and sync.
  - In-browser demo backend, unit tests, GitHub Pages workflow.
- **Phase 2, done:** people and courses.
  - Course master: categories, courses with batches and fees, fee plans, one-time charges.
  - New admission: one parent with several children and several courses each, duplicate-phone detection, live fee preview.
  - Students list (search, status and course filters) and full student profile (edit, status changes, add/edit/end courses, siblings, call/WhatsApp).
  - Backend tests run the real Apps Script code in Node (`npm run test:backend`).
- **Phase 3, done:** fees and attendance.
  - Dues engine: monthly/quarterly/half-yearly/annual plans, one-time charges, advances, partial payments, discounts, prorating, waivers. Dues are created automatically on the 1st of each month and can be generated by hand.
  - Fees & dues screen with ageing filters and WhatsApp reminders; family fee page; record payment (Cash/UPI/Bank); cancel payment.
  - Receipts numbered per financial year, saved as PDFs in the academy's Google Drive, shared from the phone or as a WhatsApp link.
  - Attendance by course, batch and day ("All present" and tap the absentees), holidays, absentee WhatsApp messages, monthly report.
  - The demo now runs the real backend code in the browser.
- **Next, phase 4:** online payments and reminder campaigns.
